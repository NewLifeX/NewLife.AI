## 2. 词表文件

- `NewLife.AI/Locales`：内核词表，31 种语言、139 条，全量翻译。
- `NewLife.ChatAI/Locales`：应用层词表，**分批迁移中**——当前已覆盖 API 网关控制器的 19 条英文键（简体中文回归原文），其余中文消息待按文件迁移；未覆盖语言回退英文。
- 文件名即 BCP 47 语言代码；英文是源文与兜底，**不需要** `en.yml`。
- 键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成压缩语言表，NativeAOT 下同样可用。

### 2.1 下游项目自带词表

`NewLife.AI` 已内置本项目全部 31 种词表，引用包即生效（`Localization.Translate` 直接命中）。下游项目若要**追加自己的**词表：

1. 在项目中直接 `PackageReference` 引 `NewLife.Core`（与 `NewLife.AI` 用的是同一版本）；
2. 项目根建 `Locales/*.yml`，无需改 csproj，Core 的 `build/NewLife.Core.props` 会自动挂载为源生成器输入。

必须**直接引用** Core，是因为 PackageReference 默认 `PrivateAssets` 含 `contentfiles;analyzers;build`，源生成器与 props 不随 `NewLife.AI` 传递；只引 `NewLife.AI` 时本项目词表照常可用，但下游自己的 `Locales` 目录不会被编译。`check-package-consumer.ps1` 覆盖了这条端到端链路的验证。

`NewLife.ChatAI` 就是按这条规则接入的：项目直接 `PackageReference` 引 `NewLife.Core`（与 `NewLife.AI` 同版本），并在项目根建 `Locales/zh-Hans.yml`。缺少直接引用时词表会被静默忽略——可用 `-p:EmitCompilerGeneratedFiles=true` 检查 `Localization.g.cs` 是否生成来确认。

## 3. 新增一条消息

1. 代码中写英文源文：`throw new ArgumentException("Message list cannot be empty", nameof(request));`，日志直接写英文模板（`Logger.Format` 自动翻译）。
2. BCL 异常与非 `XException` 异常需显式翻译：`throw new InvalidOperationException(Localization.Translate("WebSocket is not connected; call ConnectAsync first"));`
3. 在全部语言文件的同一位置补齐该键；遗漏只回退英文，不会编译失败。
4. 运行校验脚本确认键集合、占位符与格式说明符一致。

### 3.1 异常与日志的翻译路径

| 路径 | 是否自动翻译 | 说明 |
|------|:------------:|------|
| `XException` / `ApiException` | ✅ | 构造函数调用 `Localization.Translate` |
| `ToolException` / `ChatException` / `QuotaExceededException` | ✅ | 构造器内部翻译，见对应源文件 |
| `ArgumentException` / `InvalidOperationException` 等 BCL 异常 | ❌ | 调用点显式包 `Localization.Translate(...)` |
| `XTrace.WriteLine` / `Log.Info` / `WriteLog` | ✅ | `Logger.Format` 按日志语言翻译 |
| 带实例前缀日志 | ✅ | 使用 `InfoPrefixed` / `ErrorPrefixed`，前缀不参与查表 |

日志语言由 `Localization.LogCulture` 控制，与异常/界面使用的 `Localization.Culture` 相互独立。

### 3.2 Web 宿主语言识别

ChatAI 通过 `UseChatAI()` 注册的中间件按 `Accept-Language` 创建 `RequestCultureScope`：

- 仅当 `Localization.Culture` 为空时生效，宿主可固定全局语言
- 按 q 权重选择最高且已有词表的语言，未命中时保持宿主语言
- 只修改 `CurrentUICulture`，不影响协议中的数字与日期格式

## 4. 校验

```powershell
# 词表一致性（-RequireTranslated 要求所有语言均已翻译，无英文占位）
pwsh -File check-locales.ps1 -LocaleDir NewLife.AI/Locales -SourceDir NewLife.AI -RequireTranslated

# 运行时消息必须为英文（调用点不得含 CJK）
pwsh -File check-english-exceptions.ps1 -Dir NewLife.AI

# 打包与消费级验证（nupkg 资产、服务商注册表、包内词表、下游自带词表自动挂载）
pwsh -File check-package-consumer.ps1
```

CI 的 localization job 会执行前两个脚本，package-consumer 由 test 工作流的 build job 执行，任一失败即阻断合并。

### 4.1 源码消息覆盖

`check-locales.ps1` 默认还会扫描源码中的 `L.T(...)`、`XException`/`ApiException` 构造、`XTrace.WriteLine(...)`、`Log?.Info(...)`、`WriteLog(...)` 与 `Localization.Translate(...)` 字面量，要求每条消息都能在基准词表中找到对应键，防止"代码已本地化、词表漏条目"导致运行时静默回退英文。纯符号型诊断列在 `-AllowMissingMessage` 中，不参与翻译。

### 4.2 不在运行时消息范围

以下内容保持原值，不参与词表翻译：

- 持久化数据与种子数据：服务商名称、模型显示名、技能名称、菜单文案等。这些值会写入数据库并参与匹配，翻译会破坏既有数据。
- 提示词与工具描述：`System Prompt`、`[ToolDescription]`、`[Description]` 等 LLM 契约文本。
- 数据库内部标识：SQL 列别名、JSON 字段名、协议字段名等非用户可见字符串。
- 代码注释（含防御性注释）。

## 5. 最小验证

```csharp
Localization.Culture = new CultureInfo("zh-CN");
Assert.Equal("消息列表不能为空", Localization.Translate("Message list cannot be empty"));

// 未注册语言回退英文
Localization.Culture = new CultureInfo("sw-KE");
Assert.Equal("Message list cannot be empty", Localization.Translate("Message list cannot be empty"));
```

- `Localization.Culture` 是进程级全局状态，改写它的测试应放入串行集合。
- `InvariantGlobalization=true` 下具名区域性不可用，只断言英文回退。
- `AotSmoke` 关闭了 invariant，第 38 个场景在 NativeAOT 发布件中用 `zh-Hans` 实测命中词表（"工具 'search' 缺少必填参数 'kw'"）；运行环境需 ICU（Linux 装 `libicu-dev`）。
- 请求语言作用域基于 `CultureInfo.CurrentUICulture`（AsyncLocal），并行异步流互不串扰；`Localization.Culture` 非空时作用域不生效——两条都有独立测试。

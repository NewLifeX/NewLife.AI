# NewLife.AI — 需求文档

> 版本：v4.0 | 日期：2026-07-17

本文档描述 NewLife.AI 开源社区版（`NewLife.AI` + `NewLife.ChatAI`）的**愿景与核心目标、模块编码和功能方向**。完成状态统一维护在[功能清单](功能清单.md)，详细设计在[架构设计](架构设计.md)及各专项文档中展开。

---

## 1. 背景与愿景目标

### 1.1 系统定位

NewLife.AI 是面向 .NET 生态的**开源 AI 基础设施与对话应用平台**，以统一的 SDK 层和开箱即用的 Web 应用，让 .NET 开发者快速获得多模型对话、工具调用、技能系统、记忆进化等 AI 能力。

| 产品/工程 | 定位 | 说明 |
|-----------|------|------|
| `NewLife.AI` | 开源核心 AI 基础设施 | 统一接入主流模型服务商，覆盖文本、思考、视觉、图片、视频、语音、向量、函数调用、MCP、Planner、Agents 等底层能力 |
| `ChatAI` / `NewLife.ChatAI` | 开源标准 Web 对话系统和标准 AI 网关 | 提供标准对话应用、会话/消息/模型/技能/用量管理、基础 Handler 和标准网关能力 |
| `NewLife.StarChat` | 商用增强版与领域智能体运营平台 | ⚠️ **非本版本范围**，共享 ChatAI 基础能力，通过更多 Handler 和服务增强知识进化、知识库、项目、额度、审批和领域运营 |
| `NewLife.AI.Extensions` | ASP.NET Core 扩展包 | DI 注册助手 + MCP over HTTP（SSE + HTTP Stream）+ `AspNetMcpServer` |

### 1.2 愿景

NewLife.AI 的目标是成为 .NET 生态中最易用的 AI 应用基础设施：

- 通过统一的 `IChatClient` 接口屏蔽 46 家服务商的协议差异，一行代码切换任意模型
- 提供完整的 Web 对话应用，开箱即用，支持多轮对话、流式输出、多模态交互
- 通过技能系统让非开发者也能用 Markdown "教会" AI 做特定事情
- 通过用户记忆进化让 AI 越用越懂用户
- 通过 API 网关让外部系统以标准协议接入 AI 能力

### 1.3 工程分层

代码采用两层工程结构：

| 工程 | 定位 | 目标框架 | NuGet |
|------|------|---------|-------|
| `NewLife.AI` | 核心 SDK（46 客户端 / Tools / MCP / Agents / Planner / Filters / Channels / Memory / IChatHandler） | net45 / netstandard2.0 / netstandard2.1 | `NewLife.AI` |
| `NewLife.ChatAI` | ASP.NET Core Web 应用（API 控制器 + 网关 + 魔方管理后台 + 内嵌 React 前端 + 数据实体 + 业务服务） | net8.0 / net10.0 | `NewLife.ChatAI` |
| `NewLife.AI.Extensions` | ASP.NET Core DI + MCP over HTTP 扩展 | net8.0 / net10.0 | `NewLife.AI.Extensions` |

## 3. 功能需求

本章按模块编码组织功能方向。每个功能点的实现状态、测试和注释在 [功能清单](功能清单.md) 中追踪，详细设计在各专项文档中展开。

### 3.1 AI — AI Client SDK

`NewLife.AI` 是所有上层能力的基础设施，重点是统一接入不同服务商、协议和模型能力。

- **AI-1 服务商与协议适配**：当前代码扫描包含 **46 个模型服务商**，通过 `[AiClient]` 特性注册；协议适配包含 OpenAI、Anthropic Messages、Google Gemini、DashScope、Ollama、AWS Bedrock 6 类。

- **AI-2 模型能力与接口**：覆盖文本生成、流式输出、深度思考、视觉理解、图片生成/编辑、视频生成、语音识别/合成、文本向量等能力，通过统一接口和元数据标记为上层提供一致的调用体验。
  - **AI-2a 统一模型接口**：通过 `IChatClient` 统一同步与流式对话调用，上层无需直接关心各服务商协议差异。
  - **AI-2b 模型能力元数据标记**：通过模型能力标记描述 Thinking、Vision、Audio、Image、Video、Embedding、FunctionCalling 等能力，供前端和路由选择。
  - **AI-2c 函数调用与工具循环**：支持 Function Calling / Tool Use，`ToolChatClient` 可自动执行工具调用循环。
  - **AI-2d Embedding（内存向量存储）**：提供 `IEmbeddingClient` 统一接口、`HashTextEmbedder` 本地哈希嵌入和 `InMemoryVectorStore` 内存向量存储，服务知识库与 RAG 场景。
  - **AI-2e 重排序接口**：`IRerankClient` 统一重排序模型定义。
  - **AI-2f 视频生成**：已对接阿里万相文生视频能力，通过 `IVideoClient` 接口支持。

- **AI-3 MCP 与扩展点**：
  - **AI-3a MCP 客户端**：MCP 客户端在 `NewLife.AI` 核心库层提供（无 DB 依赖），支持 stdio 和 HTTP SSE 传输。
  - **AI-3b MCP 服务端**：MCP 服务端在 `NewLife.AI.Extensions` 提供，`AspNetMcpServer` 可将本系统工具暴露为标准 MCP 服务。
  - **AI-3c 过滤器与构建器**：通过 `IChatFilter`、`FilteredChatClient` 挂载审计、记忆、工具等横切能力。
  - **AI-3d ChatClientBuilder**：`ChatClientBuilder` 构建器提供链式组合 Filter 与工具的入口，简化客户端装配。

### 3.2 CHAT — 对话系统

WebUI 是用户最主要的交互入口，目标是建设标准、稳定、可扩展的 AI Web 对话系统。

- **CHAT-1 对话引擎**：
  - 多轮对话、SSE 流式输出、停止生成、重新生成、编辑消息继续对话。
  - **后台继续生成**：离开页面后生成任务继续，回来后恢复完整结果。
  - **可恢复流/断线续传**：SSE 断线后按事件 ID 恢复未完成生成。
  - **会话轮数限制**：支持设置最大对话轮数，超出限制时返回提示事件并终止本轮对话。

- **CHAT-2 会话管理**：
  - 会话列表、分组、搜索、分页加载、新建、删除、重命名、置顶和自动标题生成。
  - **对话全文搜索**：跨会话搜索消息内容并跳转定位。
  - **对话导入与导出**：支持导出和导入对话数据，便于备份与迁移。
  - **会话共享**：生成只读分享链接，用于跨用户查看对话结果。
  - **匿名分享**：支持配置允许未登录用户访问分享链接。


- **CHAT-3 模型与思考**：
  - **模型切换**：运行时选择不同模型，并根据模型能力展示思考、视觉、图像等可用功能。
  - **思考模式**：支持 fast/auto/think 三档，并展示可折叠推理过程。
  - **对话预设/Presets**：保存模型、技能、System Prompt 和参数组合，适配常用场景。
  - **助手触发词激活**：用户消息命中助手配置的触发词时自动切换激活对应助手。

- **CHAT-4 多模态交互**：
  - **附件与多模态**：支持图片、文档上传，覆盖拖拽、粘贴、点击等入口。
  - **图像生成与编辑**：支持文生图、图像编辑和前端预览。
  - **语音识别（浏览器）**：前端基于 Web Speech API 的浏览器语音输入已可用。

- **CHAT-5 消息展示与反馈**：
  - **代码与 Markdown 展示**：支持 Markdown、表格、代码高亮、复制、Mermaid、KaTeX 等渲染能力。
  - **消息反馈**：支持点赞、点踩、原因选择和文本反馈。
  - **响应式布局**：PC 左右分栏与移动端适配，保证多终端可用。

- **CHAT-6 设置与管控**：
  - **设置页面**：提供模型偏好、对话参数、个性化、技能、MCP、学习、数据管理等。
  - **技能快捷栏**：底部 SkillBar 展示常用技能，支持 `@` 触发技能选择。
  - **联网搜索**：通过内置搜索工具让 AI 获取实时信息。
  - **卡片风格系统**：三层优先级 + 自动匹配，前端风格选择器。
  - **系统公开配置接口**：标题/Logo/欢迎语等无需登录即可获取。

### 3.3 TOOL — 能力扩展

> **核心能力：工具 > 技能。** 工具决定 AI 能做什么，技能决定 AI 怎么做。能力扩展让 AI 从"会聊天"变成"能做事"。

- **TOOL-1 技能系统**：以 Markdown 管理可复用行为指令，注入 System Prompt，支持分类、启停和用户定制。
  - **触发词自动激活**：根据用户消息自动匹配技能。
  - **技能递归引用**：技能可 `@` 引用其他技能，支持深度限制和循环检测。
  - **内置系统技能**：翻译助手、案例教学、业务规则模板 3 个系统预置技能，启动时自动种子化。

- **TOOL-2 原生工具**：
  - **原生工具**：通过 `[ToolDescription]` 将 .NET 方法暴露为 AI 工具。
  - **工具审批机制**：通过 `IToolApprovalProvider` 在高风险工具执行前请求用户确认。
  - **内置工具服务**：内置搜索、天气、翻译、网页抓取、IP 定位、网络诊断、节假日、当前用户等工具。
  - **工具调用上下文透传**：`ToolCallContext` 在工具调用链路中显式透传异步上下文。
  - **工具结构化错误返回**：含 `error_code`、`hint`、`suggested_fix` 三字段的结构化 JSON，支持模型自修复。
  - **工具依赖熔断**：当外部工具服务连续失败达到阈值时暂时熔断，防止级联故障，熔断冷却后自动探测恢复。

- **TOOL-3 MCP 与横切扩展**：
  - **MCP 工具**：连接外部 MCP Server，也可把本系统工具暴露为 MCP 服务。
  - **IChatFilter 横切扩展**：在底层模型调用前后插入过滤器，适合协议级修改和无实体依赖增强。
  - **工具渐进式发现**：工具数量较多时先注入目录，再按需加载 Schema，降低上下文消耗。
  - **工具多受众内容分发**：工具可返回面向用户、模型和日志的多受众结构化内容。

- **TOOL-4 上下文与注入**：
  - **技能优先级覆盖**：用户同名技能可覆盖系统技能。
  - **知识注入预算**：为技能、记忆设置独立预算，避免 System Prompt 膨胀。
  - **注入边界策略**：稳定的全局规则置于前段，历史摘要置于中段，本轮召回内容置于末段。
  - **内置系统技能注入**：出厂内置技能由 Skill 实体 InitData 种子化，按 Code 幂等 upsert。翻译助手、案例教学、业务规则模板 3 个为系统预置。

- **TOOL-5 数据库工具**：
  - **search_table**：按关键字搜索数据库表结构（表名、注释、字段、连接名和数据库类型）。
  - **query_sql**：在指定连接上发起 SELECT/INSERT/UPDATE 并返回 JSON 结果集。
  - **数据库访问配置**：`DbAccessConfig` 配置表按连接名+角色控制白名单/黑名单，禁止 DDL 操作。

- **TOOL-6 可视化与交互**：
  - **show_widget 工具**：AI 可直接生成 SVG 图表或 HTML 片段渲染到对话气泡（流程图、时间线、关系图、数据卡片）。后端校验代码大小（≤ 200KB）并拦截远程 `<script>`，前端 sandbox iframe 隔离执行。
  - **图表可视化工具**：提供 `show_chart`（ECharts 交互式图表，JSON 规范约 200 tokens 即时渲染）、`show_timeline`（时间线）、`show_kanban`（看板）、`show_mindmap`（思维导图）、`show_china_map`（中国区域地图标注）等可视化工具，分别由 `ChartToolService`、`TimelineToolService`、`KanbanToolService`、`MindmapToolService`、`MapAnnotationToolService` 实现。
  - **文档生成工具**：提供 `build_ppt`（PowerPoint）、`build_excel`（Excel）、`build_doc`（Word）三款办公文档生成工具。AI 描述结构化内容自动排版，通过 `BuildPptToolService`/`BuildExcelToolService`/`BuildDocToolService` 生成文件并返回下载链接。
  - **图表多格式兼容**：增强图表工具对 LLM 输出的容错能力，兼容雷达图、饼图、漏斗图等多种非标准数据格式，减少因模型输出格式偏差导致的渲染失败。
  - **卡片风格系统**：三层优先级（会话 > 用户 > 系统默认）+ 自动匹配，`CardStyleHandler` 向 `show_*` / `build_*` 系列工具注入风格提示词，指导 AI 生成符合特定视觉规范的 HTML/SVG 内容。前端提供风格选择器。
  - **人类决策检查点（供 CodingAgent）**：`ask_user` 工具让 AI 在遇到不确定情况时暂停并提问。`ToolChatClient` 工具循环内置 ask_user 豁免机制（同轮同名同参工具调用去重时跳过 ask_user，确保每次调用独立提问）。CodingAgent 在控制台环境下通过 `Console.ReadLine()` 获取用户回答，自动化测试可通过 `UserInputProvider` 回调注入。

- **TOOL-7 规划器与处理器**：
  - **Planner 规划器**：`FunctionCallingPlanner` 将自然语言目标分解为多步工具调用计划并执行。
  - **处理器链（IChatHandler）**：三段式（OnBefore / Interceptor / OnAfter），在对话前后插入自定义逻辑；内置 `LearningHandler`（自动注入记忆、触发自学习分析）。

### 3.4 EVO — 知识进化（基础版）

> 知识进化是社区版的基础差异能力。用户记忆让 AI 从"对话工具"初步进化为"越用越懂你"的助手，自动从对话中提取结构化用户记忆。**高级进化能力（痛觉、好奇心、蒸馏、融合等）属商用版 StarChat 范围，不在本版本提供。**

- **EVO-1 用户记忆**：
  - **10 类用户记忆**：自动从对话中提取身份、偏好、习惯、兴趣、背景、职业、目标、人际关系、技能专长、交互指令等 10 类长期记忆。
  - **记忆注入**：每次对话前自动将相关记忆注入 System Prompt，让 AI 感知用户上下文。
  - **对话分析引擎**：`ConversationAnalysisService` 异步分析对话内容，结构化提取知识，评估置信度。

- **EVO-2 记忆管理**：
  - **记忆管理 API**：列表查询、手动添加/编辑/删除、分类筛选。
  - **推荐问题**：欢迎页展示引导性推荐问题，由管理员在后台配置。

### 3.5 GW — API 网关

API 网关让外部系统以标准协议接入 AI 能力，核心价值是在接口转发之外提供记忆注入与技能增强。

- **GW-1 多协议入站**：
  - **OpenAI Chat Completions**：`POST /v1/chat/completions`，支持流式/非流式/函数调用/视觉。
  - **OpenAI Responses**：`POST /v1/responses`，支持推理模型。
  - **Anthropic Messages**：`POST /v1/messages`，Claude 系列协议。
  - **Google Gemini**：`POST /v1/gemini/...`，Gemini 系列协议。
  - **图像生成 API**：`POST /v1/images/generations`，支持文生图。
  - **图像编辑 API**：`POST /v1/images/edits`，支持编辑修复。
  - **模型发现 API**：`GET /v1/models`，可用模型列表。

- **GW-2 认证与路由**：
  - **AppKey 认证**：`sk-` 前缀随机密钥，每个 AppKey 绑定用户身份、模型范围。
  - **模型路由**：根据模型编码选择服务商和模型。
  - **上游 429 指数退避重试**：带随机抖动，最多 5 次。

- **GW-3 用量记录**：
  - **用量记录**：每次调用记录 Token 消耗、耗时等指标，同时归属到用户与 AppKey 双维度。
  - **基础用量统计**：按日聚合，支撑用户和 AppKey 维度查询。

### 3.6 IM — 渠道集成

IM/OA 集成将 AI 对话能力延伸至企业即时通信平台，当前以基础收发和配置为主。

- **IM-1 国内主流渠道**：
  - **钉钉机器人**：接收钉钉群/私聊消息并回复 AI 内容。
  - **企业微信应用**：对接企业微信应用消息回调。
  - **企业微信机器人（群聊）**：企业微信 Webhook 群聊机器人。
  - **飞书机器人**：接收飞书消息事件并回复。
  - **微信公众号**：订阅号/服务号接入。
  - **微信客服**：客服系统接入。
  - **QQ 机器人**：QQ 官方开放平台接入。
  - **Webhook 通用渠道**：支持自定义系统回调。

- **IM-2 国际与通用渠道**：
  - **Slack 机器人**：双向收发+签名防重放。
  - **Telegram 机器人**：Token 验证+消息收发。
  - **Discord 机器人**：Gateway 长连接。

> 渠道配置管理页、定时对话任务（ChatJob）等高级管理功能属商用版 StarChat 范围。

### 3.7 AGENT — 智能体框架

提供规划器、多智能体编排等基础设施，支持复杂任务协作。

- **AGENT-1 智能体基础设施**：
  - **IAgent 统一抽象**：`ConversableAgent` 可对话智能体，支持 System Prompt + 工具 + 模型。
  - **多智能体群聊**：`GroupChat`（轮流发言 + 模型选择发言者）/ `ParallelGroupChat`（并行处理 + 汇总）。
  - **委托智能体**：`DelegatingAgent` 任务委托子智能体。
  - **智能体即工具**：`AgentAsTool` 将 Agent 包装为工具。
  - **规划器**：`FunctionCallingPlanner` 自然语言→多步工具计划，支持重规划。

- **AGENT-2 人工协同与反思**：
  - **人工确认节点 HITL**：关键决策点暂停请求确认。
  - **Reflection 反思修正**：生成→评审→修订循环。
  - **可恢复任务状态**：检测点持久化 + 断点续执行。

- **AGENT-3 度量与运维**：
  - **Agent 度量体系**：成功率/耗时/Token/工具调用指标。
  - **执行记录与经验提取**：执行结果持久化，支持智能体自我进化（LessonsLearned）。

## 5. 不做什么

- 不提供用户登录鉴权实现：由 `NewLife.Cube` 等外部权限框架统一处理，后端通过当前会话获取 `UserId`
- 不提供封闭的托管控面或商业化计费系统：计量（Metering）及计费（Billing/Pricing）是商用版平台能力
- 不替代专业桌面 Agent 或 IDE 插件：仅提供底层 AI 编排工具
- 不提供分布式部署/微服务编排方案：单进程单体部署，多实例水平扩展需自行搭配负载均衡
